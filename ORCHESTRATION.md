# Orchestration

> Referenced from CLAUDE.md. Read before fanning out subagents/workflows.

## Context propagation

Subagents get a frozen snapshot of `CLAUDE.md` + always-on rules only — not the
detail files, not files you read, not mid-session edits. The orchestrator must
**brief each subagent explicitly**: name the detail file it must read, and inline
any critical rule from `CONTRACTS.md` that applies to its task.

## Agent → layer briefing map

| Task | Detail file to name | Key rule to restate inline |
|------|-------------------|--------------------------|
| Backend handler/service/store work | `CONTRACTS.md`, `ARCHITECTURE.md` | Use `handleStoreErr()`; all persistence through `port.Store` |
| Frontend UI/feature work | `CONTRACTS.md`, `ARCHITECTURE.md` | Use `@/*` imports, `import type` for types |
| Domain model changes | `CONTRACTS.md` | Keep `types.ts` and `models.go` in sync |
| Route/layout changes | `ARCHITECTURE.md` | Never hand-edit `routeTree.gen.ts` |
| Terminal/PTY work | `ARCHITECTURE.md` | Mock fallback must work without native PTY |
| Any Go work | `.claude/rules/go.md` (auto-loads) | — |
| Any frontend work | `.claude/rules/frontend.md` (auto-loads) | — |

## Convergence files — serialize, never parallel-edit

These files are append-heavy or regenerated; parallel edits will conflict:

| File | Why serial |
|------|-----------|
| `frontend/src/routeTree.gen.ts` | Auto-generated by router plugin — any hand-edit is overwritten |
| `frontend/src/store/useDevDeckStore.ts` | Central zustand store — all features write to it |
| `frontend/src/store/types.ts` | Shared domain types — multiple features reference them |
| `backend/internal/domain/models.go` | Mirrored domain types — must stay in sync with types.ts |
| `backend/cmd/server/main.go` | Route registration — every new handler adds a line |
| `backend/internal/port/store.go` | Store interface — every new resource adds methods |
| `backend/internal/store/*.go` | Store implementation — one file per resource, but shared `db.go` |
| `frontend/src/lib/api.ts` | API client — all endpoints funnel through here |

## Parallelization pattern

1. **Scope the work-list inline** — list files, find channels, scope the diff before fanning out.
2. **Isolate file-mutating agents** in git worktrees when they touch different files.
3. **Fan out per-domain** (e.g., one agent for invoices backend, one for news frontend),
   not per-layer-across-domains (never "one agent does all handlers, one does all stores").
4. **Integration step (serial)**: resolve convergence files, run codegen (`routeTree.gen.ts`),
   run `npm run typecheck` + `go vet ./...`, run `npm run build`.
5. **Verify each agent's output** yourself — don't trust unverified claims.

## Worktree isolation

When parallel agents mutate files, isolate each in a git worktree:

```
EnterWorktree({name: "feature-invoices"})  → agent works
EnterWorktree({name: "feature-news"})      → agent works
```

Re-integrate by merging worktree branches back, or copying changed files manually
for small diffs. Run `npm run build` + typecheck after integration.
