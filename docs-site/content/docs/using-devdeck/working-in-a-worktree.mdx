Opening a worktree switches the whole screen into a **tiling workspace**:
the top header disappears, the sidebar collapses to a narrow icon rail (a
back arrow, your workspace badge, and nav icons — the only way back once the
header's gone), and the rest of the screen becomes a canvas you fill with
resizable panes, arranged however you like.

## Pane kinds

Every pane can hold one of four things:

## Splitting and arranging panes

Each pane has a small header with its own tab strip (stack several tabs in
one pane without splitting it), "split right" / "split down" buttons, and —
when the pane is focused — a "..." overflow menu. Drag a tab and drop it
near a pane's edge to split in that direction, or drop it on the center to
merge it in as another tab in that same pane.

Your layout (which panes, which tabs, how big each split is) is remembered
per worktree, so it reopens exactly the way you left it.

<Callout title="On phones">
  Panes stack one full-screen at a time instead of tiling side by side, and
  drag-and-drop is turned off.
</Callout>

## The overflow menu

On the focused pane, when its active tab is a Terminal, the "..." menu has:

- **Approve** — only shown while the worktree is waiting on you to confirm
  something.
- **Open Git panel** / **Open file explorer** — add or jump to that pane
  kind, since a fresh worktree starts out with only a Terminal pane.
- **Details** — edit the worktree's branch, task, or model.
- **Delete** — removes both DevDeck's record of it and the on-disk copy of
  the code (the agent is stopped first, if one was running).
