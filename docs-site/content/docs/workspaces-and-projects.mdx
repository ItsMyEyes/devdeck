---
title: Workspaces and projects
description: Organize your work into workspaces and projects.
---

A **workspace** is the top-level grouping — think "one client" or "one
team". A **project** is a single repo living inside a workspace.

## Create a workspace

Create one (name only) from the onboarding screen, or later from the
workspace switcher at the top of the sidebar.

## Add a project

Inside a workspace, add a project one of two ways:

- Point it at a local folder — a folder picker browses the filesystem of
  whichever machine will run the project.
- Clone a GitHub URL directly.

You'll also pick which registered **Machine** runs it.

<Callout title="Empty machine dropdown?" type="warn">
  A brand-new hub starts with no registered Machines, so this dropdown may
  be empty on a fresh install — see [Deployment
  modes](/docs/deployment-modes) for how a Machine gets registered. The
  fastest fix is running with `--role both` (or the desktop app's "Host
  locally" option), which registers itself automatically.
</Callout>

Once added, the project appears in the sidebar's project tree, with
**Worktrees** and **Issues** tabs. Continue to [Your first
worktree](/docs/first-worktree).
